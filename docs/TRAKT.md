# Trakt 影音接入

影音是独立的生活记录空间：作品、本人评分、实际观看日期和感想，帮助回顾故事与当时的自己。不会自动创建事务，也不会用观看量或类型推断人格。所有资料保存在当前浏览器，并纳入完整备份；其他设备需要导出与恢复。

## 免费 GitHub Pages 配置

1. 在 [Trakt 开发者页面](https://developer.trakt.tv/apps)创建自己的应用，按官方要求连接已验证的 GitHub 账户。
2. Redirect URI 填 `https://templehao.github.io/codex/`，包括末尾斜杠。
3. JavaScript / CORS 的 Allowed origins 填 `https://templehao.github.io`，不带 `/codex/`。
4. 打开网站的「影音」，展开「连接与资料管理」，把公开 **Client ID** 填到 Trakt 入口，点击「跳转 Trakt 授权」。不填写 Client Secret。
5. 在 Trakt 登录并同意授权，回到同一个浏览器标签页。查看预览，点击「保存到影音」才写入资料，并在此浏览器启用自动更新。

网页用 PKCE，授权网址来自 `https://auth.trakt.tv`，资料接口来自 `https://api.trakt.tv`。没有收费服务器、外部 AI 或 Trakt 写操作。Client ID 是公开应用标识；授权码、Client Secret、访问和刷新令牌不需要发到聊天中。已有的其他工具授权码不能直接导入，因为本站需要对应的临时 PKCE 校验信息。

确认保存后，每次打开网页都会自动更新，即使停留在人生看板也会读取；页面内切换栏目不会重复请求。临时 state、PKCE verifier 与回调地址仅存于当前标签页的 sessionStorage，回跳时一次性删除；本地等待窗口是 10 分钟。回调的授权参数立即从地址栏移除。访问令牌、刷新令牌与到期时间单独保存到本机 IndexedDB，用于自动续期；刷新操作通过 Web Locks 在标签页之间串行执行，成功后替换单次使用的刷新令牌。连接信息不进入工作台数据、localStorage、sessionStorage、备份、GitHub、工作流或构建产物。

旧版导入时没有保留连接，需要再跳转授权并「保存到影音」一次。以后正常打开即可自动更新；也可点击「立即更新」。网络失败时已有资料和连接保留，不自动连续重试；授权被撤销则需要重连。「断开 Trakt 连接」只删除连接并停止本浏览器自动更新，保留影音记录；「清空浏览器数据」同时删除记录、连接及图片缓存。连接不随备份迁移，另一设备首次需要授权。

## 导入内容与口径

页面默认进入「回顾」，展示所选年份相遇的电影、剧集与真实观看日；「片单」用完整作品浏览和筛选，「感想」回看自己的文字。电影和整部剧各占一张卡，详情由主动点击打开，单集收进默认折叠的分季记录，仍可查看和编辑每一集。搜索单集名称会找到所属剧集。只有单集资料、暂缺父剧时，用一张「未命名剧集」保留入口，不猜片名。

年度作品、题材分布均按整部作品去重；观看日按上海时区去重，同一天连看多集计一天。作品评分保留整部作品的本人评分，不用单集平均代替。观看历史不推定整剧看完或目前正在追。分组只用于展示，不重写原始条目、日期、评分、感想或备份；所有单集资料继续随同步和备份保留。

读取电影和单集观看历史、电影和剧集的本人评分、电影和剧集的想看列表；每个接口以 `extended=full,images` 请求完整资料与海报，逐页读取并核对分页数量。任何分页、授权或网络失败都会停止，本次资料不保存。

- 年度月份只统计明确提供的观看日。详情保留全部观看事件与重看；仅有评分或手动标记「看过」，不会生成观看日期。
- 有观看历史的电影和单集标记「看过」。父剧保留为「未分类」，单集观看不能证明整部剧已看完或正在追。
- 实际想看列表中的作品标记「想看」；仅有评分的作品标记「未分类」。可以手动补充「在看」或「看过」。
- 观看日期按中国时区展示。同一观看事件编号去重；编号对应日期冲突时整次合并失败。
- 相同作品合并历史，保留原感想及其他片单内容。新资料没有确定观看状态时，保留已有手动分类。
- 使用 Trakt 返回的作品标题；未提供的中文译名不猜测。常见类型标签有固定中文映射。
- 海报优先根据 Trakt 返回的 IMDb 编号使用公开 Metahub 封面（Stremio 官方示例所用图源），无须另一个 API Key，也不发送 Trakt 账号令牌。电影与剧集独立补图，单集继承父剧封面。
- 列表中的作品信息可能是旧快照。缺少 IMDb 或只有旧 Walter 海报时，通过 `/movies/{id}?extended=full`、`/shows/{id}?extended=full` 补查；已有有效封面复用，不重复查详情。最多 3 个并发、每次最多 500 次详情请求；遇到限流或网络故障停止补查，保留观看资料。
- 原有 Walter URL 和旧备份仍可读取。自动更新会迁移失效地址；旧片单没有持久授权但仍保留公开 Client ID 时，也会自动补图。点击「修复海报」可补地址并重新加载失败缓存，图片补丁只更新地址，不覆盖补图期间新写的评分、感想或观看记录。
- 浏览器缓存可读取的 WebP、JPEG、PNG 图片，以 Blob 地址显示，最多 100 张、单张最多 2 MB。图片服务不允许 CORS 读取时，专用 Service Worker 使用原生 `no-cors`、无凭据请求缓存公开图片，再通过本站图片地址显示；响应保持 opaque，最多 12 张。该模式依照浏览器要求使用 `redirect: follow`，无法检查最终跳转地址或不透明内容大小。允许的初始地址仅为旧 Trakt CDN 路径及固定 Metahub IMDb 路径。Worker 不缓存应用页面。
- 完整备份包含 IMDb 编号（已有时）与海报来源地址，不包含图片缓存或连接令牌。新设备重新获取图片；清空浏览器资料同时删除图片缓存。

## 海报自检

2026-10-08 的[独立 GitHub runner 检查](https://github.com/TempleHao/codex/actions/runs/37829362627)中，旧文档图片域名 `walter-r2.trakt.tv`、`walter.trakt.tv` 均未解析到地址。Metahub 公开示例返回 HTTP 200、107732 字节 JPEG，未允许 CORS。因此，只改跨域缓存或只重读个人列表不能覆盖这些故障；新版同时补详情、替换旧图源并保留不透明图片缓存。

「检查海报」区分缺少地址、等待加载、已经显示、缓存不可用、图片响应未能显示，并显示作品详情查询结果。「复制海报诊断」只包含计数与浏览器能力，不包含片名、观看记录、作品编号、图片地址、Client ID 或账号令牌。

作品详情另有「这部作品的封面诊断」，由用户主动展开和复制，包含该作品的公开 Trakt/IMDb 编号、官方作品链接与封面状态，不含观看日期、感想或账号凭据。它用于核对个别作品的缺图原因。卡片分别显示「暂无封面」「封面加载中」「海报加载失败」，避免将没有地址与下载失败混在一起。免费 IMDb 图源覆盖有限；无 IMDb 编号的节目仍需要资料源提供其他可用图片地址，不能保证所有节目自动有图。

仓库的 `Diagnose public Trakt posters` 手动工作流使用固定公开样例，检查 DNS、HTTP、真实浏览器显示、旧 Worker 升级及刷新缓存，不读取个人账号。新页面等待支持新图源的 Worker 确认就绪，避免旧控制器暂时拒绝海报。可以重新运行以区分图源变化和应用故障。

## 连接问题

「无法连接」时检查本机网络能否访问 Trakt，并核对上述回调地址和 Allowed origins。若应用刚修改设置，重新从本页跳转授权。不要把旧授权码复制到地址栏，也不要在新标签页单独打开回跳网址。

「授权信息无效或已过期」表示临时信息缺失、已被消费、超出本站等待窗口，或回跳不匹配；从本页重新开始即可。「数据不完整」表示分页或资料校验未通过，已有记录保持原样。请求频率受限时稍后主动重试，不自动连续请求。

单元与浏览器测试使用虚构账户响应，验证授权校验、读取、确认保存、失败不覆盖与备份兼容；只有用户在自己配置的 Trakt 应用完成真实授权后，才可确认其网络及账号读取成功。
