# 财务与消费回顾

「财务」把支付宝支出放进人生工作台，帮助回看花费、生活领域与自己的消费感受。目前支持导入账单文件，不连接支付宝账户，也不会自动生成待办。

## 导入你的账单

1. 在支付宝的账单页面导出交易明细 CSV，将文件保存在手机「文件」或电脑中。
2. 解锁有序，进入「财务」，点「导入支付宝账单」并选择 CSV。
3. 预览交易数量、记录期间、支出、退款、收入及合并结果，再点「确认导入」。取消或解析失败不会改变记录。

支持带说明页头的支付宝交易明细、UTF-8 与 GB18030 编码。文件最多 10 MB，本机最多 20,000 笔交易。字段包括交易时间、交易分类、交易对方、商品说明、收支、金额、付款方式、交易状态及订单号；订单号只用于生成稳定去重编号和原支付与退款之间的匿名关联，不保存原始订单号和对方账号。未支持其他平台或自定义表头。

重叠期间可再次导入：相同交易不会重复增加，状态或原交易内容变化会更新；自己标记的生活领域、固定开销等消费性质和备注会保留。不清楚用途的「亲友代付」等先归为其他，可以自己修正，不根据对方名称猜测你的关系或消费动机。

## 数字的含义

| 内容 | 口径 |
| --- | --- |
| 已支付支出 | 支出方向且状态为交易成功、支付成功、等待确认收货或充值成功的金额；已关闭交易若有精确关联的成功正额退款，原支付仍纳入，退款另扣 |
| 收到退款 | 不计收支方向且状态为退款成功的金额；退款不作为收入重复统计 |
| 收入 | 收入方向且交易已成功的金额 |
| 不计收支 | 还款、账户之间转动等成功的中性流水，避免重复计入消费 |
| 处理中 | 尚在处理或未识别的交易状态，暂不计入确认收支 |
| 已关闭 | 没有成功退款佐证的关闭交易，以及失败或取消的交易，保留明细供核对，不计入支出 |
| 支出减退款 | 期间已支付支出减去期间收到的退款；退款可能来自以前的消费，因此不等于这个月最终消费成本 |

金额按整数分计算。退款以原订单号的匿名哈希关联原支付，避免全额退款后的关闭交易被重复扣减；不按相同金额猜测关联。按月查看仍使用整份已导入账单的关联信息。未找到原支付的退款保留为到账退款，可能来自以前的消费。支付宝文件摘要可能包含未完成支付或使用其他统计口径，预览会同时展示文件摘要。账单仅代表已导入的账户记录，不代表资产余额、负债或全部家庭开销。

## 在人生看板中回看

首页展示账单累计数量、所选月份的已支付支出，以及最近按天汇总的消费记录。财务页可切换月份、生活领域和支付宝原分类；支出分布按已支付金额展示，退款单独呈现。明细的关键词、生活领域和收支类型筛选只影响明细，不改变概览口径；每页 15 笔。

原交易记录保留，可补充消费性质和备注。「固定开销」仅统计自己标记的交易。点「写下回顾」可以把自己的消费感受保存为人生看板中的财务发现，不改写账单。

## 保存与更新

账单在浏览器内读取，确认后纳入本机工作台密文，不上传 GitHub、博客或外部 AI。完整备份包含财务交易、分类、备注和导入覆盖期间；恢复旧备份不会清掉已有账单。导出 JSON 备份为明文，请保存在自己控制的位置。

以后导入新的 CSV 才会更新账单，刷新网页不会自动向支付宝取数。旧交易的实际状态也需要通过后续导入更新。详见 [本机口令与加密](LOCAL_SECURITY.md) 和 [数据与备份](DATA_AND_BACKUPS.md)。
