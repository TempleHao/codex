# 聊天收集约定

用户可以随意叙述生活和工作中的事情，由聊天助手理解、整理，再导入网页。网页导入器不替代语义分析，也没有访问聊天历史的权限。

整理时请遵循：

1. 将明确要做的事写成具体、可执行的下一步。大的目标可以拆成少量下一步，避免自动扩展成用户未提出的长期计划。
2. 背景、情绪、已完成的事放入原文或备注，不自动变成待办。用户说“不要做”时，不建立对应的正向任务。
3. 多次提到的同一件事可合并；保留关键条件、先后关系、联系人与材料在备注里。
4. 明确区分计划日期与截止日期。不要为了填满列表而猜测优先级、承诺或截止日。
5. 相对日期按收集当时的上海日期解释，并把日期解释告诉用户。“下周找时间”“月底前后”等不确定表述保持日期为空，将问题放入 `needsClarification`。
6. 周期需求写进备注和待确认项。当前网页不支持自动重复，不能声称周期提醒已建立。
7. 每条尽量保留原文中的短摘录 `sourceExcerpt`；完整原话放在 `sourceText`。
8. 先展示中文待办概览和需要确认的问题，再给出可直接复制的 JSON 代码块。一次不超过 100 条。

输出结构：

```json
{
  "version": 1,
  "sourceText": "用户原话",
  "tasks": [
    {
      "title": "一个可执行动作",
      "notes": "背景、条件和材料",
      "area": "生活",
      "priority": "normal",
      "plannedDate": null,
      "dueDate": null,
      "needsClarification": [],
      "sourceExcerpt": "原话中的对应片段"
    }
  ]
}
```

允许的领域：`生活`、`工作`、`健康`、`阅读`、`出行`、`思考`、`其他`。优先级为 `normal` 或 `high`。所有日期为 `YYYY-MM-DD` 或 `null`。

可直接对聊天助手说：

> 请按照人生工作台的聊天收集约定，把以下原话整理成待办。保留原话，区分计划日期和截止日期，含糊的地方标为待确认。先让我看懂你怎么拆分，再给出 version:1 的导入 JSON。不要自行安排没说过的事情。

在同一次聊天继续补充或撤回事项时，先更新整理结果，再导入最终一批。网页目前没有“聊天消息自动同步”或“已导入任务自动修改”的能力；若是修改既有事项，请在页面编辑，避免再导入成重复任务。
