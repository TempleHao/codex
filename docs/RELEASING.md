# 版本与发布

每次发布都应让使用者知道更新了什么、如何使用以及是否影响已有资料。项目以 `package.json` 的版本为唯一软件版本来源，网页也读取这个值。`CHANGELOG.md` 保存完整说明，GitHub Release 保存对应标签和说明，Pages 展示这个提交构建的应用。

## 更新约定

- 当前处于 0.x 开发阶段：较大的功能或产品改动提升次版本，例如 `0.2.0 → 0.3.0`；修复、文案、样式或文档更新提升修订版本，例如 `0.2.0 → 0.2.1`。
- 每次推送正式更新到 `main`，同时更新软件版本、锁文件、当前版本的更新记录与受影响的文档。不要用同一个已发布版本承载新的提交。
- 说明写给使用者：具体改了什么、使用方式变化、数据兼容性和真实限制。不要把计划或未通过的验证写成已完成。
- 阅读与博客定时同步、相同提交的部署重试不会提高软件版本，也不会重复创建 Release。
- 已发布标签固定到原提交，不移动、不覆盖、不删除。发布后发现问题，补发新版本修复。
- 软件版本、完整备份格式 v2、阅读库格式 v1 和图片缓存协议是不同编号，不能一起随意升级。

## 准备一次发布

在仓库根目录执行，例如下一次修复版：

```sh
npm version patch --no-git-tag-version
```

这个命令只更新 `package.json` 和 `package-lock.json`，暂不创建 Git 标签。较大功能可改用 `minor`。

在 `CHANGELOG.md` 顶部新增当前版本的章节，日期用实际发布日：

```markdown
## [0.2.1] - 2026-10-10

- 写明本次具体变化。
- 如有使用或数据变化，一并说明。
```

更新 README 的当前版本和相关指南，执行 `npm run release:check`，再按改动范围运行类型检查、测试和静态构建。PR 或提交说明应记录实际验证结果。检查没有夹带个人资料，提交完整改动并推送 `main`。

## 自动发布顺序

工作流 [.github/workflows/pages.yml](../.github/workflows/pages.yml)负责：

1. 校验版本号、锁文件、有效日期与当前版本说明；如果该标签已属于另一个提交，立即停止，避免用旧版本发布新代码。
2. 完成类型检查、单元测试、静态构建和可选微信读书加密读取。
3. 部署 GitHub Pages。
4. 在 `main` 的代码推送或手动发布时，为同一个提交自动创建 `vX.Y.Z` 标签和 GitHub Release，说明取自 CHANGELOG 当前章节。独立定时数据同步不会创建 Release；其他分支不部署或发布。

独立 [sync-data.yml](../.github/workflows/sync-data.yml) 每 3 小时读取微信读书与博客资料，复用当前提交的 Pages 构建 artifact；博客每月全量核对。无可用 artifact 时会触发只同步数据的 Pages 运行。定时运行可能延迟，GitHub 对长期无活动仓库的计划任务可能停用，不保证永远按时执行。

发布任务单独使用 `contents: write` 权限，构建任务仍为只读。无需创建个人访问令牌，不上传个人备份、阅读快照或凭证为 Release 附件。GitHub 自动提供对应源代码的 ZIP/TAR 下载。

自动发布流程要求仓库允许 Actions 使用上述权限。Fork 的维护者可以采用同样流程；未配置微信读书 Secrets 时仍可以部署基础工作台。

## 重试与验收

部署或 Release 失败时先查看失败步骤和原因。修复环境或权限后，可对**相同提交**重新运行工作流；已经发布的同版本会保留，不重复创建。如果需要修改代码或发布配置，请提升版本号并新增记录。

部署成功而 Release 失败时，网页可能已更新，不能只凭网页可访问就宣称版本发布完成。最终确认 Actions 的部署与发布任务都成功、Release 标签指向正确提交，实际网页页脚显示对应版本且资源可访问。

本地维护者如需补建已经成功部署的版本，可在该提交的干净工作目录使用已认证的 GitHub CLI：

```sh
node scripts/release.mjs --publish --repo TempleHao/codex --commit 完整的40位提交编号
```

脚本会验证标签不能属于其他提交。不要对未验证、未部署的提交使用这个命令；不要移动已有标签。

## 历史版本

首个正式记录的版本是 **v0.2.0**。更早的工作保留在 Git 提交历史及 CHANGELOG 的日期里程碑中，没有人为补造当时不存在的 Release。
