# 自动更新资料

网页仍是静态 Pages 应用，数据更新由 GitHub Actions 发布快照，浏览器打开时读取快照。阅读和博客来源不是浏览器直接实时请求官方平台；页面拿到的是最近一次云端同步结果。日常使用不依赖 Codex 在运行。

## 云端计划

`sync-data.yml` 每 3 小时尝试运行一次，计划时间为 UTC 01:17、04:17、07:17、10:17、13:17、16:17、19:17、22:17。它读取微信读书（包括笔记）并增量更新博客。每月 1 日 01:17 UTC 会对博客历史做全量核对。定时工作流复用同一提交已构建的 Pages artifact，不重复运行全量构建与测试；artifact 已过期或不存在时会触发 `pages.yml` 的只同步运行。数据同步不创建新 Release，Pages artifact 保留 90 天。

`pages.yml` 负责代码变化后的完整校验、构建和部署，并同步数据；代码部署成功后才创建对应软件版本 Release。成功部署后，每 30 天在独立的 `data-maintenance` 分支记录一次不含个人内容的维护时间，减少仓库长期无活动的情况；它不修改主分支代码或创建软件版本。GitHub 定时任务仍可能延迟或因平台规则被停用，计划时间不构成持续运行保证。需要尽快更新时，可在 GitHub Actions 手动运行相应工作流。

## 浏览器读取

打开页面、或页面保持打开/返回前台满 15 分钟后，会检查微信读书、博客和 Trakt 三个来源。Trakt 在当前浏览器直接请求官方接口并自动更新；连接需保存在该设备。

微信读书首次需输入专用解锁口令，读取、预览并保存。保存时可勾选本设备自动解锁。之后页面用 IndexedDB 中不可导出的 PBKDF2 CryptoKey 解密最新快照并合并到本机阅读库。浏览器不保存原口令或 API Key。每台设备需单独启用；关闭自动解锁会删除密钥并保留现有阅读记录。更换口令后需重新解锁。

博客同步文件为公开内容，在每次打开时通过同站点 `blog-sync.json` 的 `no-store` 请求获取。网络或读取失败时保留本机 IndexedDB 缓存，下次再试。博客缓存独立于生活工作台和完整 JSON 备份。

## 资料更新与限制

更新流程以完整校验后的数据替换快照；同步失败不会发布半份数据。定时任务不等同于实时推送，平台新增内容要等下一次同步、部署及浏览器重新读取后才出现。GitHub 调度、Actions 用量和平台接口可用性均可能影响更新。
